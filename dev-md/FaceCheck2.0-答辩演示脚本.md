# FaceCheck 2.0 答辩演示脚本

> 建议演示时长：6-10 分钟  
> 演示设备：华为 Pad  
> 演示目标：证明 FaceCheck 已从“刷脸签到 Demo”升级为“可解释、可配置、可导出、可维护”的课堂考勤系统。

## 1. 开场介绍

FaceCheck 是一款基于 HarmonyOS 的课堂刷脸签到 App。2.0 版本围绕课堂真实使用场景做了四个增强：

- 课程和班级组织：学生属于班级，可选课程，发起签到时按课程冻结名单。
- 地理围栏防作弊：老师发起签到时记录 Pad 所在位置，学生刷脸前再次校验 Pad 是否仍在课堂范围内。
- 活体与人脸比对：可选交互式活体检测，随后进行 1:1 人脸比对。
- 记录和解释：正式签到、缺勤、失败尝试都能被记录和导出，失败原因可追溯。

## 2. 演示路线

### 2.1 设置与诊断

操作：

1. 打开“设置”页。
2. 展示人脸阈值、迟到判定、活体检测开关。
3. 展示“地理围栏默认策略”：默认开关、默认半径、定位超时。
4. 点击“导出诊断摘要”。

讲解要点：

- 设置项通过 Preferences 持久化，不是 UI 假开关。
- 新建签到场次会读取默认位置策略。
- 诊断摘要只导出版本、能力、设置和统计，不导出隐私明细。

截图建议：

- 设置页完整截图。
- 诊断摘要保存成功提示。

### 2.2 演示数据和教学组织

操作：

1. 在设置页点击“生成演示数据”。
2. 切到“教学”页。
3. 展示 DEMO 班级、DEMO 课程和选课关系。

讲解要点：

- 演示数据带有明确 DEMO 标识，便于清理。
- 系统使用课程作为签到名单来源，发起场次时会冻结本场应到名单。

截图建议：

- 教学组织页中 DEMO 班级和课程。

### 2.3 人脸录入

操作：

1. 切到“人员”页。
2. 选择一名测试学生，进入人脸录入。
3. 使用前置摄像头录入正脸照片。

讲解要点：

- 人脸录入会做人脸检测和质量校验。
- 人脸照片保存在应用沙箱，设置页可清理敏感数据。

截图建议：

- 人脸录入成功状态。
- 人员列表中“已录入人脸”状态刷新。

### 2.4 发起带地理围栏的签到

操作：

1. 回到“签到”页。
2. 点击“发起签到”。
3. 选择课程，确认地理围栏默认开启。
4. 点击“使用当前 Pad 位置”。
5. 创建签到场次。

讲解要点：

- 本项目采用教师 Pad 设备模式：记录的是签到设备位置。
- 之后每次刷脸前都会再次检查 Pad 是否仍在签到地点范围内。
- 不做后台持续定位，降低权限和隐私压力。

截图建议：

- 发起签到弹窗。
- 定位成功的地理围栏卡片。

### 2.5 刷脸签到成功

操作：

1. 选择已录入人脸的学生。
2. 点击刷脸签到。
3. 若开启活体，完成系统活体动作。
4. 完成人脸比对并展示签到成功。

讲解要点：

- 流程顺序是：位置校验 -> 活体检测 -> 人脸检测 -> 1:1 比对 -> 写入记录。
- 出勤圆环和本场统计会随签到实时刷新。
- 实时动态列表会展示成功状态和匹配分数。

截图建议：

- 签到成功结果卡片。
- 出勤圆环变化。
- 实时动态列表。

### 2.6 失败尝试可解释

操作：

1. 可选：拒绝位置权限、取消活体或选择未录入人脸学生。
2. 回到记录页查看失败尝试。
3. 导出 CSV。

讲解要点：

- 失败尝试不会污染正式出勤率。
- 老师仍能看到失败阶段和原因，例如位置失败、活体失败、人脸比对失败。
- CSV 可用于课后复核。

截图建议：

- 记录页失败尝试。
- CSV 导出成功提示。

## 3. 答辩关键词

- ArkTS + ArkUI 原生开发。
- Core Vision Kit 人脸检测与 1:1 比对。
- Vision Kit Interactive Liveness 活体检测。
- Location Kit 前台即时定位。
- ArkData RelationalStore v4 数据持久化。
- Preferences 设置持久化。
- 课程名单快照，避免场次过程中名单变动影响统计。
- 失败尝试日志，提升系统可解释性。
- 横竖屏自适应和 PlanUI 统一设计系统。

## 4. 结束说明

FaceCheck 2.0 当前重点是稳定交付教师 Pad 版课堂签到。后续如果继续扩展，可以考虑学生端定位、蓝牙/校园 Wi-Fi 辅助校验、教师端课程统计看板和云端同步，但这些不影响当前期末版本的核心闭环。
